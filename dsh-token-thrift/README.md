# dsh-token-thrift

让 DSH **花得聪明**，而不只是被卡住上限。

## 它和 `dsh-agent-budget` 的分工

[`dsh-agent-budget`](https://github.com/vibeinging/dsh-agent-budget) 做的是**准入**：每次请求服务商
之前判断"这笔花得起吗"，花不起就拒绝。那是"限制"，也很有价值——它保证你不会超支。

本插件做**另一半**：在还没超支的时候，让同样的活花更少。它**不拒绝任何请求**，只做两件事：

1. **按花费升级劝告**——花到预算的一档，就往上下文里注入一条提醒，从"读文件前先想想要不要读"
   到"别再探索了，交活"。
2. **遮罩会开枝的工具**——到了后段，把 `subagent` / `workflow` / `ralph` 从该 agent 的工具表里
   摘掉。

> **省 token 最有效的一招不是少说几句，而是不要再开新的分支。** 每开一个子 agent，整段上下文
> 都要在新会话里重新读一遍——那是这个系统里最贵的一次复制。

两者可以同时装：一个兜底，一个省钱。

## 看得见

教练做的事没有反馈：往上下文里塞一句提醒、把工具从表里摘掉，两样都悄无声息。所以它带两个界面。

### 左下角的浮球（可交互）

落在**左下角**（吉祥物在右下角），常驻一颗 40px 的球，点开是一个**能改东西的面板**。面板是半透明的 ——
它压在你正在读的东西上面，一块不透明的板子是拿来关掉的，不是拿来瞟一眼的。

- **球**：一片**流体粒子场**，没有边框，也没有数字。**颜色随花费变**——绿到黄到橙到红；
  **流速和密度随力度变**，所以热档的球肉眼就是另一个东西。拖一下换位置（记在本机），点一下开面板。
  工具被遮了角上多一个 ⛔，过了阈值还没遮是一个 `!`。精确百分比在 `title`、`aria-label` 和面板里——
  球上不写数字，是为了让它**一眼可读**而不必去读。
- **点开**：上半是控件 —— 一条 **1–100 的力度滑杆**、预算输入框（应用 / 恢复）、本会话重置；
  下半是它现在在做什么 —— 进度条上标出每一档的位置（响过的点亮）、已响几档、已提醒几次、
  遮了哪些工具，以及「已过阈值，下一次工具调用时遮罩」这类中间状态。

**控件长在面板里，不是只长在控制台里。** 要看一眼就得离开去操作的界面，最后就没人打开了。
力度和预算改完立刻生效：POST 回来的是新的整份快照，面板照着它重画，而不是照着乐观猜测。

### 控制台（完整版）

打开 `GET /dsh-token-thrift/console/`。同样是那些控件，外加**全部会话**的列表和原始 JSON，
适合排查而不是随手调一下。面板右下角的「全部会话 ↗」直接跳过去。

两处写的都是**运行时覆盖**，重启回到 profile 里的值；两处都会显示「配置里是什么」和
「现在是什么」，以及哪几项被覆盖了。

## 数据从哪来

教练的状态原本只活在一个以 agent 为键的 `WeakMap` 里 —— 对教练是对的形状，对外面任何东西
都不可达。所以主驾那边每走一步会额外写一份按 session 归类的快照（最多留 8 个会话），
胶囊和控制台读同一份。

两个刻意的选择：

- **没启用时接口照样应答**，页面会说"未启用，budget 是 0"，而不是让角落空着让人以为坏了。
  也因此可以从控制台把它打开：工具监听器是随设置装/卸的，不是启动时定死的
  —— 而"关闭时不留监听器"这条仍然成立。
- **每条快照带着它自己那份档位表**。控制台能在会话中途改档位；拿新表去画旧报告的"已响"，
  会声称某一档响过而其实没有。

## 为什么是"提醒"而不是"拒绝"

一个跑在自动驾驶上的 agent，最贵的失败不是"多花了几千 token"，而是**"被中途掐断、活没干完"**。

所以本插件默认只劝告。`maskTools` 是唯一的硬手段，而它遮的是**枝**，不是**活**：主线的读写、
检索、编辑都还在，agent 仍然能把活干完。

## 配置

先给预算，再拖力度。**力度只管劝，不管遮** —— 遮罩是另一根滑杆：

```yaml
- name: file:///path/to/dsh-token-thrift/lib/index.js
  config:
    budget: 2000000        # 0 = 关闭（默认）
    intensity: 55          # 1–100；0 是关闭，-1 是"没人说过"（默认）
    maskAt: 25             # 花到预算的 25% 就把会开枝的工具摘掉；0 = 永不遮。上限 50
    maskTools: [subagent, subagent_fork, workflow, ralph]
```

力度这条线改变的是**劝**：劝几次、从多少开始。

- `1–30`：1–2 档，从九成到七成半开始劝
- `31–60`：2 档，从七成半到六成
- `61–85`：3 档，从六成到三成半
- `86–100`：4 档，从三成半到两成半

**为什么把遮罩从力度里拆出来。** 原来两者绑在一起，而那条线能把遮罩阈值压到最低 55% ——
预算 200 万时就是 **110 万 token**。一个普通会话到不了那儿，所以遮罩从来没有发生过，看上去
就是"这个功能没用"。现在它是自己的旋钮，默认 25%（200 万时 50 万），上限 50%：比这更晚就跟
旧行为没有区别，没必要留个旋钮假装能调。用百分比而不是比例，是因为读的人想的是"花到几成就摘"，
不是"0.25"。

**为什么不直接用 dsh-ops 那种静态隐藏。** [dsh-ops](https://github.com/T-Auto/dsh-ops) 在
`cordis.patch.yml` 里用独立组件静态换掉官方工具，不依赖会话比率 —— 那是"永远不要这个工具"的
需求。这里要的是"花超了才不要"，所以是运行时的 `tools.restrict()`。两种都成立，别混用。

**拒绝要说出来。** `tools.restrict()` 对未注册的工具名、对非 scoped 的上下文都会抛错。原先那个
`catch` 把它整个吞掉，于是「还没到阈值」「被宿主拒绝」「已经遮上」三种状态从外面看一模一样。
现在拒绝的理由会进快照，面板里用红字写出来 `遮罩没生效：…`。

**为什么是一条线而不是四个名字。** 变狠这件事只有一个方向：劝得更早、劝得更多。
原来那四个名字本来就是这条线上的四个点，而中间那三段没有理由够不着。刻意的 0 与「没人说过」
是两件事，所以配置里的默认值是 `-1` 而不是 `0` —— 否则一个把力度设成 0 的 patch 会悄悄回退到
`level`，把教练又打开。

写着的是运行时覆盖，重启回到文件里的值；面板和控制台都会显示"配置里是什么"和"现在是什么"。

**每一档说的话由它**所在的位置**决定，不由它是第几档**：一个落在 85% 的档位在哪儿都应该说"收尾"。
如果按序号取词，一个只有一档的柔和设置就会在烧掉九成的时候礼貌地建议"养成更省的习惯"。

老写法还能用：`level: light / standard / strict / off` 现在是这条线上的四个停靠点
（25 / 55 / 100 / 0）。`tiers` 和 `maskRatio` 手写了仍然优先。

## 花费从哪来

读 DSH 自己的 `tokenUsage` 投影，不自己记账。理由是投影已经是权威口径，自己再算一份迟早会和它对不上。

读法有个讲究：用 `ctx.get("sessionProjections")`，**不是** `ctx.sessionProjections`。Cordis 对没有
`inject` 声明的服务不是返回 undefined，而是**抛错**；这一行在 `tools/post-execute` 里，所以一次读错
会让**整个会话的每一次工具调用都失败**。`ctx.get` 是官方给"我没注入但想读一下"的入口，服务不在时
返回 undefined，正是这段代码本来就假设的行为。

口径：`inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`。

**`reasoningTokens` 不加**——它已经在 `outputTokens` 里，再加一次会让每个读数都虚高一个思考预算。

## 测试

```sh
node test/run.mjs
```

52 项，**不启 DSH**：造一个够用的伪 ctx，把钩子拿出来直接驱动。测的是插件的逻辑（哪一档该响、
响几次、什么时候遮工具），而不是 DSH 能不能起来——后者用
`dsh --profile <名字> --dump-config` 验。

伪 ctx 里有两个刻意的设计：`get()` 和**会抛错的属性读取**。区别就是这插件曾经翻车的地方——
以前那版伪 ctx 把服务当普通属性挂着，于是测试全绿而真机上每次工具调用都挂。

浏览器半边也在这里测：用桩 `window.__ModuleLoader__` 把 bundle 加载进来，验它注册的 id
等于包名、注册进 `shell.overlay`、子 slot 是 `session-maybe`，以及 `pickReport` 按 session
匹配而不是取最新那条。

面板的**外观**由 `.scratch/thrift-look.mjs` 保证（仓库外，用真 React + 无头浏览器把五种状态
渲染出来看），浮球的流体场由 `.scratch/ball-look.mjs`（五档 tone 各渲一颗，并读出 canvas 的
实际尺寸与平均不透明度）。单元测试证明接线对，证明不了它可见——没有高度的 div、和背景糊在一起的
颜色、永远不涨的进度条，都是只有看一眼才知道的事。

流体场的两个数是**被测量钉住**的，不是调着好看：`flow` 必须让 40px 的球里装下至少一个完整涡旋，
否则所有粒子同向漂移、轨迹叠成拉丝条纹（第一版就是这样，测试会报
「0.055 gives 0.35 periods across 40px」）；`prefers-reduced-motion` 下跑的是同一段积分预热 70 帧
再冻住，而不是另写一套静态画法——手写静态版只到 5/255 平均不透明度，看着像个空球。

## 已知边界

- **不保证不超支。** 那是 `dsh-agent-budget` 的事。本插件只在事后按比例劝告，中间那一步花多少
  它管不着。
- **`tools.restrict` 不存在时不会失败**——提醒照发，只是遮不了工具。为了一个可选的优化而中断
  整轮，是不划算的交易（有测试守着）。
- **它自己出错也绝不会失败工具调用**。钩子里任何没处理到的异常都被吞掉、原样放行——理由同上，
  而且这不是假设：这个插件曾经因为一个未声明的服务读取，把整个会话的工具链一起打死。
- **只劝告，不阻断**。想要硬停，去装 `dsh-agent-budget`。
